# MD-015: Replication spool operations

Replication-enabled uploads spool one verified input copy before uploading it to storage nodes. The spool is kept in `MINIDRIVE_REPLICATION_SPOOL_DIR` (default `./data/replication-spool`), a dedicated MiniDrive directory. Do not point it at a general temporary directory. The directory must be writable and exclusively owned by one backend instance; a file lock prevents two instances from using or cleaning the same directory.

Defaults are a 5 GiB maximum per spool, 5 GiB total process-local reservation, one concurrent spool, a 1 GiB minimum free-space reserve, and a filesystem capacity check every 16 MiB while streaming. The per-file default preserves the existing 5 GiB resumable-upload limit when the filesystem has enough space. The per-file limit and total budget are independent; operators can set a smaller aggregate budget, in which case some uploads below the per-file limit can be rejected for capacity. Environment bindings are `MINIDRIVE_REPLICATION_SPOOL_DIR`, `MINIDRIVE_REPLICATION_SPOOL_MAX_FILE_BYTES`, `MINIDRIVE_REPLICATION_SPOOL_MAX_RESERVED_BYTES`, `MINIDRIVE_REPLICATION_SPOOL_MAX_CONCURRENT`, `MINIDRIVE_REPLICATION_SPOOL_MIN_FREE_BYTES`, and `MINIDRIVE_REPLICATION_SPOOL_CHECK_INTERVAL_BYTES`.

The expected size is reserved before reading. The actual stream is counted and rejected if it exceeds the expected or configured size. Capacity and concurrency rejections return 503 with `Retry-After`; a per-spool size rejection returns 413. The request is never truncated or uploaded after a failed spool. The permit and reservation stay held through node upload and verification, and are released with spool-file deletion on completion or failure.

Active operation and reserved-byte gauges are `minidrive_replication_spool_active` and `minidrive_replication_spool_reserved_bytes`. Rejections, spool I/O failures, cleanup failures, and recovered files have bounded-cardinality counters under `minidrive_replication_spool_*`. Monitor these with the host/container filesystem's free space and error logs; tune limits to the actual volume capacity and workload.

Reservations are process-local and do not impose an operating-system quota. The directory lock requires each backend instance to use its own directory. If instances share a host or volume, give each a separate instance directory and size the volume for their combined budgets, or enforce an OS/container volume quota. Other processes may still consume disk between checks, so the free-space reserve is a guard, not a host-wide guarantee.

At startup, after acquiring the exclusive directory lock, MiniDrive removes only files matching its `md-repl-*.spool` pattern. This safely recovers files left by a crashed prior owner; a second live instance cannot acquire the lock. Failed cleanup is logged and counted. Its file size remains reserved and cleanup is retried before a later spool admission and again after restart. Keep the spool on disposable/recoverable local storage; it contains transient copies, not the authoritative object store.
